# 双服务共存方案与成本账

> 问题：一张 11G 的 2080Ti 上，LLM（9.8G）+ ComfyUI 生图（峰值 11G）无法共存。共存只有三条路：显存变大 / 一方变小 / 错峰用同一块。

## 三方案对比

| 方案 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **A 换 24G 卡** | 云上 3090/4090 或自购 | 花钱（云差价 ~160/月，自购一次几千上万） | 两个服务都是常驻主力 |
| **B 错峰调度** | 守护脚本：生图任务提交时自动停 LLM → 跑完自动拉起 | 0 成本，但 LLM 冷启动 30-60s；正在 chat 会被打断 | 生图低频、LLM 为主力 |
| **C 分区降级** | LLM 减层（-ngl 40→20）+ ComfyUI lowvram 小模型 | 双方都降级 | 预算极敏感、能忍慢 |

## 方案 B 细节（错峰调度，0 成本备选）

```
平时：LLM 常驻全速
有人提交生图任务 → 守护脚本自动优雅停 LLM（释放 9.8G）
                  → ComfyUI 全速跑 1-3 分钟
                  → 完成后自动拉起 LLM
```

- ✅ 满足"不人肉杀进程"的诉求——脚本自动协调
- ❌ LLM 冷启动重载 27B 约 30-60s；正在 chat 的会话会被打断
- 调度方向取决于使用频率：生图低频 → LLM 常驻、生图抢占；反过来则 LLM 按需拉起

## 推荐部署配置（方案 A，24G 卡）

```bash
# llama-server 先启动（静态分配，显存不够会直接报错）
# 保持 -ngl 40（约 9.8G），24G 上甚至可去 --no-kv-offload 让 KV 上卡（更快，多占 ~1-2G）
# ComfyUI 后启动（auto 模式，不手动 --lowvram），让它自己探测剩余 ~14G → qwen-image 全上卡
```

- 启动顺序无所谓对错，但 **llama-server 先起更稳**：ComfyUI 是动态的（不够会降级），llama-server 是静态的（不够会报错）
- qwen-image 在 24G 上全上卡零 offload，比 2080Ti offload 硬撑（17s/步）快数倍

## 成本账：云租 vs 自购 vs 本地

| 路线 | 月成本（24h 常驻） | 一次性投入 | 风险/麻烦 |
|---|---|---|---|
| 云租 3090 | ~1210 元/月 | 0 | 无 |
| 云租 4090 | ~1370 元/月（包月 1100-1400） | 0 | 无 |
| 自购二手 4090 | 电费 ~280 元/月 | 1.1-1.3 万 | 矿卡/翻新风险；≈ 租 16 个月云 |
| 自购 5090D | 电费 ~400 元/月 | 1.65 万起 | 显存溢出（你只需 21G） |
| 自购 5070Ti | 电费 ~220 元/月 | 6100-8400 | 16G 装不下 21G，不满足需求 |

## 决策结论

- **图省心/体验** → 云上 4090（差价每月仅 ~160 vs 3090，速度翻倍，值得）
- **长期自建（>2 年）** → 二手 4090 或全新 5090D，但要接受二手风险或显存溢出
- **预算敏感 + 生图低频** → 方案 B 错峰调度，0 成本继续用 2080Ti
- **最终决定（2026-08）**：升级云上 4090 24G，走方案 A。
