# ADR —— 架构 / 功能设计决策记录

> 轻量 ADR（Architecture Decision Record）日志。本项目的记录偏「业务功能设计决策」而非纯架构，
> 用于沉淀「后端接口怎么设计、前端怎么配合、为什么这么取舍」这类讨论结论，避免每次靠口头记忆。

## 约定

- 文件名：`NNNN-短横线小写标题.md`，序号递增，永不回收、永不改名（只可新增「替代」决策）。
- 每篇结构（按需精简，不必每项都写）：

  ```
  # NNNN 标题
  状态: 提议(proposed) | 已接受(accepted) | 已废弃(superseded) | 已拒绝(rejected)
  日期: YYYY-MM-DD

  ## 背景 / 动机（为什么需要这个决策）
  ## 决策（我们决定怎么做）
  ## 备选方案（考虑过但没选的，及原因）
  ## 影响 / 后果（正面 + 代价）
  ## 关联（引用的接口/文档/其他 ADR）
  ```

- 状态变更：不覆盖旧记录，新开一篇引用旧的并标记 `superseded`。
- 一篇只解决一个问题，避免大杂烩。
